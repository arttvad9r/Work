# Исследование RuStore для WorkTime

Дата проверки: 2026-09-04.

Цель: подготовить первую карточку WorkTime в RuStore на основе актуальных правил площадки, требований к разработчику и того, как оформлены заметные приложения из той же предметной области.

## Что делают заметные приложения категории

### Календарь рабочих смен

RuStore: `com.lrhsoft.shiftercalendar`

- 100 тыс.+ скачиваний, рейтинг 4,8, возраст 0+;
- основная категория — `Полезные инструменты`;
- используются теги `Личные финансы`, `Работа`, `Календарь`;
- название сразу объясняет основной сценарий: календарь рабочих смен.

### График смен — Simple Shift

RuStore: `com.groviapp.shiftcalendar`

- 90 тыс.+ скачиваний, рейтинг 4,8, около 1,4 тыс. оценок;
- 7 скриншотов;
- категория `Полезные инструменты`, теги `Работа`, `Календарь`;
- сводка RuStore по отзывам отдельно отмечает удобный интерфейс, визуализацию графика, цветовое решение, дизайн и скорость работы.

### Табель учета рабочего времени

RuStore: `com.dev.workshiftcalendar`

- 20 тыс.+ скачиваний;
- 5 скриншотов;
- возраст 0+;
- `Полезные инструменты` + теги `Личные финансы`, `Работа`, `Календарь`, `Калькуляторы`, `Личные помощники`;
- описание сразу обещает два ключевых сценария: фиксацию рабочего времени и расчёт зарплаты в календаре;
- в свежих отзывах повторяется претензия к большому количеству рекламы. Для WorkTime отсутствие рекламы — реальное и полезное отличие, которое можно указывать без сравнительных формулировок.

### Табель учета рабочего времени

RuStore: `wtdevteam.worktimeplus`

## Отдельный ориентир по качеству карточек

СберБанк Онлайн используется только как ориентир по уровню store-презентации, а не как визуальный шаблон для копирования. На актуальной странице RuStore у приложения пять карточек, то есть сильная галерея не обязана перечислять каждую функцию: важнее несколько крупных, быстро считываемых сценариев и единая арт-дирекция.

Для WorkTime принято отказаться от финального формата «полный screenshot + подпись». Технические карточки, подготовленные на первом этапе, остаются только временными материалами. Финальная серия проектируется по `STORE_CARDS_ART_DIRECTION_RU.md`:

- 6 вертикальных карточек 1080×1920;
- реальный UI WorkTime является главным графическим объектом;
- одна сильная мысль на кадр;
- крупная типографика и минимум вторичного текста;
- единая сетка, цвет, глубина и формы на всей серии;
- допускаются crop, scale, перспектива и композиция нескольких настоящих экранов;
- не изображаются функции, которых нет в release-сборке;
- не используются чужие интерфейсы, логотипы и универсальные stock-phone mockup как основной художественный приём.

## Выводы для WorkTime

1. Название должно начинаться с бренда, но сразу раскрывать задачу. Поэтому подготовлено `WorkTime — учёт смен и часов`, а не просто `WorkTime`.
2. Для личного календаря смен наиболее устойчивый выбор — `Полезные инструменты`, а не `Бизнес-сервисы`: приложение не является корпоративной системой работодателя.
3. Возрастная маркировка `0+` соответствует содержанию WorkTime и большинству прямых аналогов; перед отправкой её всё равно нужно подтвердить в актуальной форме RuStore.
4. Первый кадр должен объяснять основной сценарий без чтения полного описания: календарь, смены, часы и доход.
5. Полезные отличия WorkTime, которые подтверждаются сборкой: отсутствие рекламы и аккаунта, работа основных функций без обязательного интернета, локальное хранение рабочих данных, светлая/тёмная темы, годовые итоги, виджет, экспорт и импорт.
6. Не копировать оформление конкурентов и не использовать агрессивное ASO. Текущие правила RuStore предостерегают от кликбейта, эмодзи, повторяющихся спецсимволов и навязчивого повторения ключевых слов.

## Актуальные требования RuStore, учтённые в подготовке

- название — до 30 символов и должно быть уникальным;
- короткое описание — до 80 символов;
- подробное описание — до 4000 символов;
- до 5 поисковых тегов только из списка RuStore;
- хотя бы один контакт разработчика обязателен;
- APK и AAB поддерживаются; APK должен быть подписан цифровым сертификатом;
- для обновлений пакет и подпись должны совпадать с предыдущей опубликованной версией, а номер версии увеличиваться;
- для телефона требуется не менее 3 скриншотов, максимум 10;
- изображения должны показывать актуальную функциональность, не содержать чужой интерфейс и соответствовать требованиям RuStore к формату;
- финальная WorkTime-галерея проектируется в 1080×1920;
- иконка подготовлена 512×512, с заполненным фоном и основана на реальной установленной иконке WorkTime;
- для первой публикации выбран ручной режим, чтобы после модерации отдельно проверить финальную карточку;
- форма безопасности данных должна заполняться по точной сборке и с учётом пользовательских данных, а не только Android permissions;
- соглашение RuStore требует предоставить пользователям сведения о разработчике, ссылку на политику конфиденциальности и ссылку на пользовательское соглашение.

## Privacy и юридическая модель

Текущая release-модель WorkTime local-first:

- основные рабочие записи и настройки находятся на устройстве;
- приложение не запрашивает Android `INTERNET`;
- нет рекламы, аналитики и автоматического crash-reporting SDK;
- WorkTime не отправляет автоматически разработчику рабочие записи, сведения о доходе или настройки;
- экспорт и импорт запускаются только явным действием пользователя через системный file picker.

При этом юридическую документацию нельзя сводить к фразе «мы ничего не собираем». После публикации появляется как минимум отдельный канал взаимодействия с разработчиком: пользователь может самостоятельно написать в поддержку и передать e-mail, текст обращения и вложения. Этот поток должен быть описан отдельно от локальных данных приложения.

Соглашение RuStore в текущей редакции прямо требует сведений о разработчике, контактов, ссылки на privacy policy и user agreement и закрепляет самостоятельную ответственность разработчика за обработку персональных данных пользователей его продукта.

Поэтому принято UX-решение:

- убрать `Конфиденциальность` из основной секции `ДАННЫЕ` настроек как равноправный функциональный пункт;
- оставить внизу настроек визуально спокойную ссылку `Конфиденциальность` с нормальным 48 dp touch target;
- открывать по ней отдельную полноэкранную краткую privacy-страницу;
- полную юридическую политику публиковать по постоянному публичному URL и указывать в RuStore;
- не смешивать краткое in-app объяснение поведения приложения с полным документом оператора персональных данных.

RuStore отдельно требует проверять категории пользовательских данных, не ограничиваясь manifest permissions. В их классификации зарплата приведена как пример `Других финансовых данных`, поэтому ставка/ожидаемый доход должны быть проверены в актуальном разделе `Безопасность данных пользователя` после загрузки APK, даже несмотря на локальную обработку.

Для публичного канала поддержки до релиза также нужно отдельно проверить требования 152-ФЗ: фактическую инфраструктуру e-mail, локализацию данных граждан РФ, возможную трансграничную передачу и обязанность уведомить Роскомнадзор до начала обработки персональных данных. Эти вопросы внесены в release checklist вместо необоснованного обещания, что наличие local-only приложения автоматически освобождает разработчика от всех обязанностей оператора.

## Подпись после утраты ключа 0.1.0

Приватный ключ, которым был подписан ранний прямой GitHub-релиз `0.1.0`, утрачен и не может быть восстановлен из публичного APK или отпечатка сертификата.

Публичной установленной пользовательской базы на `0.1.0` нет; разработка ведётся через отдельный debug package. WorkTime ещё не публиковался в RuStore, поэтому существующей RuStore signing identity также нет.

Принято решение:

- создать новый developer-controlled production key локально;
- считать `0.2.0` первой фактической production identity;
- использовать новый ключ для первой RuStore-версии и всех дальнейших production APK;
- использовать тот же сертификат для RuStore и прямого распространения, если direct APK продолжит публиковаться;
- старую `0.1.0` на тестовом устройстве при необходимости просто удалить перед установкой нового production APK.

В репозитории добавлен `scripts/init_production_signing_key.sh`. Он предназначен только для запуска на доверенном локальном компьютере: создаёт RSA 4096 keystore вне репозитория, экспортирует публичный сертификат и обновляет только публичный fingerprint в `release/production-signing-cert-sha256.txt`.

## Почему APK, а не AAB

Для первой публикации WorkTime оставлен путь через подписанный APK:

- размер приложения мал, поэтому выигрыш split-доставки сейчас невелик;
- APK оставляет приватный ключ полностью под контролем владельца проекта;
- RuStore поддерживает такой путь и требует стандартно подписанный APK;
- после утраты старого ключа важнее сначала закрепить новую единую signing identity для `0.2.0+`, чем одновременно вводить дополнительную инфраструктуру AAB/upload key.

Это не ограничивает будущий переход на AAB. При переходе нужно отдельно настроить ключ загрузки и подпись приложения согласно актуальной инструкции RuStore.
