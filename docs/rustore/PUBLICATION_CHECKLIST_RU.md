# Чек-лист публикации WorkTime в RuStore

Использовать для первой публикации и повторять для каждой новой версии. Все проверки относятся к точному APK, который будет загружен в RuStore.

## 1. До сборки

- [ ] `versionCode` больше всех ранее опубликованных и распространявшихся версий WorkTime.
- [ ] `versionName` соответствует релизу и пользовательскому описанию изменений.
- [ ] Кандидат находится в `main` и не содержит незакоммиченных изменений.
- [ ] `docs/PRIVACY.md`, политика конфиденциальности и пользовательское соглашение соответствуют фактической сборке.
- [ ] В финальном manifest нет неожиданных permissions.
- [ ] В dependency graph нет незаявленных аналитических, рекламных, сетевых или crash-reporting SDK.

## 2. Новый постоянный ключ подписи

Ключ, которым был подписан прямой GitHub-релиз `0.1.0`, утерян. Для первой публикации в RuStore создаётся новая production identity. В RuStore приложение ещё не публиковалось, поэтому магазин не требует замены уже зарегистрированного сертификата.

- [ ] На доверенном локальном компьютере выполнить `sh scripts/init_production_signing_key.sh`.
- [ ] Новый ключ создан как RSA не менее 2048 бит; helper проекта использует RSA 4096.
- [ ] Пароль хранилища и пароль ключа сохранены в менеджере паролей.
- [ ] Сделаны минимум две зашифрованные резервные копии `.jks` в разных местах.
- [ ] Одна резервная копия реально открыта через `keytool -list -v`.
- [ ] Новый публичный SHA-256 сертификата записан в `release/production-signing-cert-sha256.txt` и закоммичен.
- [ ] Сам `.jks`, пароли и приватный ключ не попали в GitHub, RuStore-описания, issue, PR, CI или чат.
- [ ] Старый fingerprint `0.1.0` больше не используется как production pin для `0.2.0+`.

## 3. Подписанный APK 0.2.0

Для первой публикации выбран APK, а не AAB. Размер WorkTime мал, а APK оставляет ключ подписи полностью под контролем владельца проекта.

- [ ] Собрать `WorkTime-0.2.0.apk` через `./scripts/build_release_candidate.sh` с новым release keystore.
- [ ] Проверить APK через `apksigner verify --verbose --print-certs`.
- [ ] SHA-256 сертификата совпадает с новым fingerprint в `release/production-signing-cert-sha256.txt`.
- [ ] SHA-256 APK совпадает с `SHA256SUMS.txt` кандидата.
- [ ] Точная эта же новая подпись будет использоваться для RuStore и любых прямых GitHub-релизов `0.2.0+`.
- [ ] Не пересобирать и не переподписывать APK после финальной QA без полного повторения проверки.

### Важно для пользователей GitHub 0.1.0

Новый сертификат **не может** обновить установленный `0.1.0` поверх старой версии. Это ограничение Android, а не RuStore.

Поддерживаемая миграция:

1. В `0.1.0` экспортировать JSON.
2. Сохранить файл вне каталога приложения.
3. Удалить `0.1.0`.
4. Установить `0.2.0+` из RuStore или новый прямой APK.
5. Импортировать JSON.
6. Проверить записи и настройки.

- [ ] Инструкция по миграции добавлена в заметки прямого релиза для существующих пользователей `0.1.0`.
- [ ] Не обещать бесшовное обновление с `0.1.0` — его больше невозможно обеспечить без старого приватного ключа.

## 4. Функциональная проверка кандидата

- [ ] Свежая установка проходит на физическом Android-устройстве.
- [ ] Обновление **между сборками, подписанными новым ключом** проходит без удаления приложения.
- [ ] Создание, изменение и удаление записи работают.
- [ ] Премии, штрафы и почасовая ставка дают ожидаемые итоги.
- [ ] Переключение месяца и года работает жестами и кнопками.
- [ ] Месячная и годовая сводки совпадают с контрольным ручным расчётом.
- [ ] Светлая, тёмная и системная темы переключаются корректно.
- [ ] JSON экспорт/импорт и CSV экспорт работают через системный выбор файла.
- [ ] Виджет отображает актуальные данные месяца.
- [ ] Крупный шрифт и узкий экран остаются пригодными для использования.
- [ ] Нет крашей, зависаний и блокирующих ошибок.

## 5. Карточка RuStore

Использовать значения из `docs/rustore/LISTING_RU.md`.

- [ ] Название: `WorkTime — учёт смен и часов`.
- [ ] Категория: `Полезные инструменты`.
- [ ] Возраст: `0+`.
- [ ] Поисковые теги выбраны только из актуального списка RuStore.
- [ ] Короткое и полное описания вставлены без эмодзи, кликбейта и обещаний отсутствующей функциональности.
- [ ] Заполнено поле «Что нового» для 0.2.0.
- [ ] Указан хотя бы один публичный контакт поддержки.
- [ ] Загружена `docs/rustore/assets/rustore-icon-512.png`.
- [ ] Загружено не менее 3 вертикальных скриншотов; рекомендуемый комплект — все 6 файлов из `docs/rustore/assets/`.
- [ ] В превью RuStore ни один скриншот не обрезал важный текст или интерфейс.

## 6. Юридические сведения

Соглашение RuStore требует сведений о разработчике, политики конфиденциальности и правил/пользовательского соглашения.

- [ ] В `PRIVACY_POLICY_RU.template.md` заменены все `<...>` на реальные сведения.
- [ ] В `TERMS_RU.template.md` заменены все `<...>` на реальные сведения.
- [ ] Готовые документы переименованы без `.template` и опубликованы по постоянным публичным URL.
- [ ] В документах указаны реальные наименование/ФИО, страна, юридический и фактический адрес, ИНН и контакт.
- [ ] Ссылки открываются без авторизации в обычном браузере.
- [ ] Данные в документах совпадают с данными аккаунта разработчика RuStore.

## 7. Безопасность данных пользователя

- [ ] После загрузки APK проверить автоматически найденные RuStore permissions.
- [ ] Чувствительных permissions в текущей сборке быть не должно.
- [ ] Для пользовательских значений ставки/дохода проверить декларацию типа `Другие финансовые данные`.
- [ ] Если текущая форма RuStore различает локальную обработку и передачу, отметить локальное использование для функциональности приложения и отсутствие передачи разработчику/третьим лицам.
- [ ] Не скрывать локально вводимые данные, если актуальная форма RuStore требует их декларировать.
- [ ] Текст декларации не противоречит `docs/PRIVACY.md` и публичной политике.

## 8. Отправка на модерацию

- [ ] Выбрать ручную публикацию.
- [ ] Проверить карточку на телефоне/в превью консоли.
- [ ] Отправить точный проверенный APK на модерацию.
- [ ] Не менять APK, версию, подпись или метаданные кандидата после финальной QA без повторной проверки.
- [ ] После статуса «Готова к публикации» ещё раз проверить карточку и только затем опубликовать на 100% аудитории.

## 9. После публикации

- [ ] Открыть публичную карточку WorkTime в RuStore и проверить название, иконку, скриншоты, тексты, контакты и декларацию данных.
- [ ] Установить WorkTime из RuStore на чистое устройство.
- [ ] При следующей версии проверить обновление через RuStore с **тем же новым сертификатом**.
- [ ] Добавить ссылку/бейдж RuStore в README и другие публичные страницы проекта после появления постоянной карточки.
- [ ] Следить за отзывами и отвечать на конкретные проблемы; повторяющиеся жалобы переносить в backlog.
